Key design principle

Deterministic risk scoring (Tree-sitter facts, graph fan-in, test coverage) happens before any LLM call. The LLM gets grounded context — not a raw diff to guess about.

Sequential queue

PRs processed one at a time via asyncio.Queue worker — no parallel pipeline executions, predictable resource usage. Queued PRs show "Queue #N" in the dashboard.

Custom Thinking — The Twist

4 layers of hallucination reduction

① Deterministic evidence gate

Every finding's cited file+line is cross-checked against the actual diff and read context — before any LLM grades it. No file → finding discarded.

② Hedge-word severity cap

"may", "could", "might lead to" — a finding using these words is force-capped to minor regardless of what the LLM labeled it.

③ Concrete-trace requirement

Prompt requires a specific input → code path → wrong behavior for every major/blocking finding. Risk categories without a trace are rejected.

④ Independent second critic call

The LLM that wrote a finding never grades it. A separate LLM call judges actionability and repo-context consistency — same blind spot can't produce and approve the same hallucination.

Limitations & Next Steps

Honest gaps — and the plan

Known limitations

  • !Python/JS/TS only — other languages get raw diff review, no call-graph context
  • !One global critic threshold — no per-dimension calibration yet
  • !No org-specific rules — general-purpose prompt; no knowledge of team conventions like "controllers must not call repos directly". A .pr-agent-rules.yml in the repo root would fix this.
  • !No learning from past reviews — every review starts from zero. Findings the team dismissed will be repeated; no signal to improve precision over time.
  • !No dashboard auth · Chatbot degrades on very large repos

Next steps

  • →Week 1: Go + Java grammars; .pr-agent-rules.yml support; per-dimension thresholds
  • →Week 2: Dashboard auth; GitHub App auth; multi-turn chatbot memory
  • →Feedback loop: thumbs-up/down on findings → tune critic threshold from real reviewer signal, not a fixed cutoff
  • →Large repo efficiency: incremental graph updates (re-parse only changed files); graph-size–aware context budget; eval dataset to measure precision + recall per dimension
